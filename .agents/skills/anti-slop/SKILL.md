# Anti-Slop Principles & Guidelines

## 1. Writing & Language Rules
- **No AI Buzzwords**: Avoid overused AI jargon such as *delve*, *testament*, *unleash*, *tapestry*, *beacon*, *seamless*, *groundbreaking*, *game-changer*, *transformative*, *synergy*, etc.
- **Direct & Concise**: Lead with the answer or action. Remove fluff, superficial pleasantries, and repetitive summaries.
- **Natural & Human Tone**: Write clear, professional, grounded Indonesian/English without dramatic prose.
- **No Generic Filler**: State facts and technical details directly instead of using vague importance statements.

## 2. Code & Engineering Standards
- **No Code Slop**: Do not write redundant wrapper functions, unnecessary abstraction layers, or dead code.
- **No Swallowed Errors or Silent Fallbacks**: Always handle errors explicitly with meaningful diagnostics instead of silent fallbacks or dummy mock data.
- **Self-Documenting Code**: Avoid obvious line-by-line comments that repeat what the code does. Comment *why*, not *what*.
- **Preserve Clean Architecture**: Keep components focused, types strict, and imports minimal.
